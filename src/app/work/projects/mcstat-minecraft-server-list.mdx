## Find servers players actually join

Most Minecraft server lists rank by whoever bought the most votes. MCStat starts from a
different question: is anyone actually playing? Every server on the list is pinged
continuously, so the player count next to a listing is the count right now — not what the
owner typed into a form.

Today the platform tracks **6,732 servers**, sees around **225,000 players online** at any
moment, and peaks near **250,000 a day**. It is the highest-traffic product I run.

## What it does

- **Live server pages** with player counts, uptime history, ping latency, version and
  software detection, country, tags, and a copyable IP.
- **Vote rankings** on a rolling period, with anonymous voting and abuse controls.
- **50,000+ player profiles** carrying name history, skin and texture history, session
  records, and a searchable cape gallery.
- **A forum** with categories, topics, reports, and a word filter.
- **A self-serve ad marketplace** — server owners buy labelled sponsored slots directly,
  with campaigns, invoices, and webhook-driven billing events.

## The plugin

Pinging a server from the outside only tells you how many people are on it. For owners who
want more, [MCStat-Plugin](https://github.com/mcstatorg/MCStat-Plugin) runs on Bukkit,
proxy, and hybrid stacks and streams signed HTTPS telemetry straight from the machine:
player sessions, TPS, vote links, and dashboard-ready analytics.

## How it is built

The runtime is split by responsibility on purpose, into separate systemd services:

- the **website** serves pages and nothing else,
- the **ping worker** hammers thousands of servers on its own schedule,
- the **Discord bot** runs apart from both,
- and **maintenance** runs on a timer rather than staying resident all day.

The website should not restart because the bot crashed. The ping worker should not compete
with the web server for CPU inside the same process. Splitting them is what keeps a list
this size responsive.

At the SEO layer the catalogue is well past 100,000 crawlable URLs — servers, players,
capes, forum topics — so sitemaps are sharded, canonicals are explicit, and every listing
page carries structured data.
